# Data

Three kinds of data, with different rules.

| Folder | What | Committed? | Loader |
|---|---|---|---|
| `data/synthetic/` | Seeded synthetic datasets with known truth | yes (generated, never edited by hand) | `mktstats.data.load_synthetic`, `load_truth`; R reads the CSVs |
| `data/real/` | Small real datasets whose licence allows redistribution | yes | `load_prop99`, `load_sbg_retention` |
| download cache | Larger real datasets, fetched on first use and checked with sha256 | no | `load_cdnow`, `load_mmm_example`, `load_online_retail_ii`, `load_hillstrom` |

The download cache is `$MKTSTATS_CACHE`, default `~/.cache/mktstats`. `MKTSTATS_OFFLINE=1` forbids
downloads; a missing file then raises with the URL to fetch by hand and the path to save it at.
When `mktstats` runs outside a checkout (Colab), committed files are fetched from raw GitHub at
`$MKTSTATS_REF` (default `main`).

## Synthetic data (`data/synthetic/`)

Written by `python scripts/make_synthetic.py` from the generators in `src/mktstats/synth/` with
their default seeds (numpy `Generator(PCG64(seed))`, numpy 2.1.3). `python scripts/make_synthetic.py
--check` exits 1 if regenerating would change any file; CI runs it. All true parameters, the
definitions behind them (ROAS window, units, discounting) and the recovery tolerances the tests use
are in `truth.json`. Generated by this repository's code, under the same licence as the code (MIT).

| File | Rows | Size | Generator (seed) | Contents |
|---|---:|---:|---|---|

Retailer time conventions: rates are per week; transactions carry calendar dates; summarize them
with `time_unit="D", time_scaler=7` (pymc-marketing) to get recency and T in weeks. The
calibration period ends 2024-12-29 and the holdout ends 2025-12-28.

## Real data committed here (`data/real/`)

### `prop99.csv` — California Proposition 99 (Abadie, Diamond & Hainmueller 2010)

- 1,209 rows: 39 states x 1970-2000. Columns: state, year, cigsale (per-capita cigarette sales in
  packs; California 1988 = 90.1), lnincome, beer, age15to24, retprice. Missing values are empty.
- Source: the `smoking` dataset of the R package **tidysynth 0.2.1** (Eric Dunford), CRAN source
  tarball https://cran.r-project.org/src/contrib/tidysynth_0.2.1.tar.gz (sha256
  `046b416b437dd2f3d5610ac6a594db1c941c3cf9c208becfdfed0a76ce553281`), downloaded 2026-10-09.
  tidysynth documents the data as the panel used by Abadie, Diamond & Hainmueller (2010),
  "Synthetic control methods for comparative case studies: Estimating the effect of California's
  tobacco control program", JASA 105(490): 493-505, with source https://economics.mit.edu/files/11859.
- Licence: tidysynth is released under MIT (`LICENSE`: YEAR 2020, COPYRIGHT HOLDER Eric Dunford).
- Processing: `data/smoking.rda` loaded in R 4.6.1 (workshop Docker image), written to CSV, sorted
  by state and year, numbers rounded to 7 significant digits (the values are single precision in
  the original; e.g. `89.80000305` becomes `89.8`). File sha256
  `0ba552d2250f8e8bffc6500f33858beff3378a3027213fb7507b019ec6fc3132`.
- Note: tidysynth's help page labels cigsale "pack per 100,000 people"; the values (around 90-130)
  are per-capita packs, the unit used by Abadie et al.

### `sbg_retention.csv` — Fader & Hardie (2007) retention counts

- 13 rows: year 0-12, survivors out of 1,000 customers in the "regular" and "highend" segments.
- Source: Table 1 of P. S. Fader and B. G. S. Hardie (2007), "How to project customer retention",
  Journal of Interactive Marketing 21(1): 76-90
  (https://faculty.wharton.upenn.edu/wp-content/uploads/2012/04/Fader_hardie_jim_07.pdf).
  The percentages were transcribed from pymc-marketing 1.2.0's notebook
  `docs/source/notebooks/clv/sbg.ipynb` (raw file at tag 1.2.0, fetched 2026-10-09), which states
  that they are Table 1 of the paper and asserts that its simulated cohorts reproduce years 0-7;
  counts = percentage x 10. **Not checked against the PDF itself**: the PDF was downloaded but its
  text could not be extracted (embedded font encoding). The paper's MLE estimates quoted in the
  same notebook: regular alpha = 0.704, beta = 1.182; highend alpha = 0.668, beta = 3.806.
- Licence: survivor counts are published facts from a table, reproduced with citation.
- File sha256 `e619efd9109441a1049f0bc852d47761be383365845154b0f3b5082ef79bdff9`.

Notes on Online Retail II: the zip holds `online_retail_II.xlsx` with two sheets (525,461 and
541,910 rows, 1,067,371 in total, matching the UCI page). The sheets overlap on 1-9 Dec 2010:
1,088 invoice numbers (22,523 rows, identical in both sheets) appear twice, so
`load_online_retail_ii` drops the second sheet's copy and returns 1,044,848 rows for 5,942
customers (checked 2026-10-09).
Duplicate lines inside a sheet (6,865 and 5,268) and cancellations are kept as published. Parsing
the xlsx with openpyxl took about 40 s on an Apple Silicon laptop; the result is cached as parquet.
`load_online_retail_ii(sample=...)` keeps a random subset of customers for QUICK runs.
